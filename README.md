# Парсер звёзд (Paid Reactions) в постах Telegram-канала

Консольное приложение на Python: подключается к Telegram **пользовательским аккаунтом**
(MTProto / Telethon), проходит по *N* последним постам канала, находит посты, на которые
отправляли **звёзды**, определяет отправителей и сохраняет результат в Excel.

```
Введите наименование/id канала (или несколько через запятую): @channel, t.me/another
В очереди 2 каналов: My Channel, Another Channel
Введите количество последних постов для анализа: 10000
Каждый канал анализируем по 10000 последних постов.

===== Канал 1 из 2: «My Channel» =====
(id последнего сообщения: 12345)
Парсинг сообщений: 100%|██████████| 10000/10000 [00:43<00:00, 233 сообщ./s, со звёздами: 794]

Файл сохранён: C:\apps\stars_parser\output\2025-03-04_05-06-07_My Channel.xlsx
Проанализировано постов: 10000
Пропущено служебных сообщений: 31
Постов со звёздами: 794
Записей в таблице: 2140
Не расшифровано отправителей (not_found): 168 (помогает прогрев кэша: --warmup)
Время парсинга: 43 сек (233 сообщ./с, сетевых запросов: 132, ожидание между запросами: 4 сек)

===== Канал 2 из 2: «Another Channel» =====
...

===== Итог по очереди: 2 каналов по 10000 постов =====
  1. «My Channel» — постов: 10000, со звёздами: 794, записей: 2140, файл: 2025-03-04_05-06-07_My Channel.xlsx
  2. «Another Channel» — постов: 10000, со звёздами: 12, записей: 30, файл: 2025-03-04_05-07-01_Another Channel.xlsx
Готово: 2 из 2, файлов: 2, записей всего: 2170
```

---

## 1. Возможности

* вход по готовой `*.session` или по коду из Telegram (+ облачный пароль 2FA, до 3 попыток);
* канал задаётся как `@username`, `username`, `t.me/...`, `t.me/c/<id>`, `t.me/s/<username>`,
  числовой id (без префикса `-100`, например `1234567890`, либо в `-100...` виде);
  при ошибке — повторный запрос ввода;
* **очередь каналов**: несколько каналов через запятую (`@durov, t.me/telegram, 1234567890`)
  обрабатываются по очереди, для каждого сохраняется свой Excel (см. раздел 3.1);
* **быстрый пакетный парсинг**: сообщения читаются пачками, задержка выдерживается только
  между реальными запросами к Telegram, отправители звёзд запрашиваются по 200 штук одним
  `users.getUsers` и несколькими запросами параллельно (см. раздел 5);
* прогресс-бар, автоматическая обработка `FloodWaitError` (ожидание `seconds + 1`,
  продолжение с того же места и адаптивное увеличение интервала между запросами);
* устойчивость: ни одна ошибка отдельного сообщения, реактора или пересылки не роняет программу;
* «умное» определение отправителя: пользователь / канал / аноним / неизвестно;
  при отсутствии `access_hash` в кэше сессии остаётся id и `not_found`;
* опциональный прогрев кэша участников группы обсуждения (больше найденных username);
* Excel: шапка жирным, закреплённая первая строка, автоширина колонок, автофильтр,
  id — целыми числами (без экспоненциальной записи);
* безопасное имя файла: санитайзер для названий вроде `SupernovaElit Premium|Chat️`;
  при занятом файле — суффикс `_1`, `_2`, ...;
* логи в `parser.log`, краткий вывод в консоль; `conf.ini` и сессии в лог не попадают;
* Ctrl+C — корректное завершение **с сохранением уже собранных данных**.

## 2. Требования

* Python **3.10+** (проверено на 3.11), Windows 10/11 (Linux/macOS тоже работают);
* api_id / api_hash с <https://my.telegram.org> → *API development tools*.

## 3. Установка и запуск

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # Linux/macOS

pip install -r requirements.txt

copy conf.example.ini conf.ini    # Linux/macOS: cp conf.example.ini conf.ini
notepad conf.ini                  # заполните [API]

python main.py
```

Дальше приложение само спросит канал и количество постов.

### Необязательные аргументы

| Аргумент | Назначение |
|---|---|
| `-c, --config PATH` | путь к `conf.ini` (по умолчанию — рядом с приложением) |
| `--channel VALUE` | канал без интерактивного ввода (`@name`, ссылка, id); несколько каналов — через запятую, они станут в очередь |
| `-n, --count N` | сколько последних постов анализировать (одинаково для каждого канала очереди) |
| `--output-dir DIR` | куда сохранить xlsx (перекрывает `[OUTPUT] DIR`) |
| `--warmup` / `--no-warmup` | включить/выключить прогрев кэша участников |
| `--create-empty-file` | создать xlsx только с шапкой, если звёзд не найдено |
| `--log-level LEVEL` | `DEBUG`, `INFO`, `WARNING`, `ERROR` |

Пример полного неинтерактивного запуска:

```bash
python main.py --channel "https://t.me/durov" -n 500 --output-dir results
```

### 3.1 Очередь каналов (несколько через запятую)

Каналы можно задать сразу пачкой — они становятся в очередь и обрабатываются
последовательно, одним подключением и одной сессией:

```bash
python main.py --channel "@durov, t.me/telegram, 1234567890" -n 1000
```

В интерактивном режиме список вводится в ответ на приглашение
`Введите наименование/id канала (или несколько через запятую):` — точно так же,
через запятую.

Как устроена очередь:

* разделители — запятая, точка с запятой и перевод строки (удобно вставлять список
  из блокнота); пустые элементы отбрасываются, повторы учитываются один раз,
  порядок ввода сохраняется — он же порядок парсинга;
* количество постов (`-n/--count`) задаётся один раз и применяется к каждому каналу;
* каждый канал сохраняется в **свой** файл `output/YYYY-MM-DD_HH-MM-SS_<канал>.xlsx`;
* канал, который не удалось получить (приватный, удалён, опечатка), пропускается
  с сообщением, а очередь продолжается; если не получен ни один канал — ввод
  запрашивается заново;
* ошибка во время парсинга одного канала не останавливает остальные: канал
  помечается как ошибка, парсинг идёт дальше;
* `Ctrl+C` сохраняет данные текущего канала и останавливает очередь — в сводке
  видно, какие каналы не были обработаны;
* троттлинг общий на всю очередь: увеличенный после `FloodWait` интервал
  сохраняется и для следующих каналов (статистика запросов при этом считается
  по каждому каналу отдельно);
* в конце печатается сводка по очереди: сколько каналов готово, сколько файлов
  и записей, какие каналы завершились ошибкой.

Код завершения: `0`, если обработан хотя бы один канал; `1`, если очередь не дала
ни одного результата (все каналы завершились ошибкой); `130` — при прерывании.

## 4. Конфигурация `conf.ini`

Файл лежит рядом с `main.py` (или с `stars_parser.exe`). Если его нет — приложение
выводит понятную ошибку и завершается с кодом `2`.

```ini
[API]
ID_API=1234567
HASH_API=0123456789abcdef0123456789abcdef
PHONE=+79991234567
CLOUD_PASSWORD=            ; облачный пароль (2FA); пусто — спросит в консоли

[SESSION]
NAME=anon                  ; файл сессии anon.session
DEVICE_MODEL=SM-G991B
SYSTEM_VERSION=Android 14
APP_VERSION=8.8.2
LANG_CODE=en

[DELAY]
MESSAGES_INTERVAL_MIN=0.05 ; random.uniform(MIN, MAX) между запросами к Telegram
MESSAGES_INTERVAL_MAX=0.1

[SPEED]
PER_REQUEST_DELAY=true     ; пауза между запросами, а не после каждого сообщения
HISTORY_WAIT_TIME=0        ; 0 — не ждать между пачками истории, auto — как в Telethon
MESSAGE_BATCH=500          ; сколько постов обрабатывать одной пачкой
ENTITY_BATCH=200           ; сколько донаторов получать одним запросом (лимит API 200)
CONCURRENCY=3              ; одновременных запросов к API
RESOLVE_UNKNOWN_PEERS=true ; пробовать донаторов без access_hash (пачкой, hash=0)
```

Дополнительные (необязательные) секции:

| Секция | Ключи |
|---|---|
| `[PROXY]` | `ENABLED`, `TYPE` (`socks5`/`socks4`/`http`), `ADDR`, `PORT`, `USERNAME`, `PASSWORD`, `RDNS` — нужен `pip install python-socks` |
| `[SPEED]` | `PER_REQUEST_DELAY`, `HISTORY_WAIT_TIME`, `MESSAGE_BATCH`, `ENTITY_BATCH`, `CONCURRENCY`, `RESOLVE_UNKNOWN_PEERS` — всё об ускорении, см. раздел 5 |
| `[PARSER]` | `WARMUP_PARTICIPANTS`, `WARMUP_LIMIT`, `MAX_ATTEMPTS` (повторы ввода кода/пароля) |
| `[OUTPUT]` | `DIR` (по умолчанию `output`, `.` — рядом с приложением), `FILENAME_MAX_LENGTH`, `CREATE_EMPTY_FILE` |

Правила валидации: `ID_API` — целое число, `HASH_API` и `PHONE` — не пустые,
пустой `CLOUD_PASSWORD` = пароля нет, при `MIN > MAX` значения меняются местами
(с предупреждением в логе).

## 5. Скорость парсинга

Парсер работает **пачками**, а паузы выдерживает только между реальными запросами
к Telegram. Примерное время прогона:

```
N/100 запросов истории  +  ~N/MESSAGE_BATCH запросов за донаторов  +  ожидание между запросами
```

Для 10 000 постов при `MESSAGE_BATCH=500` это ~100 запросов истории и ~30 запросов
за донаторов вместо 10 000 пауз и ~500 поштучных `get_entity`.

Что именно ускоряет работу:

1. **Пауза между запросами, а не между сообщениями.** История приходит по 100 постов
   за запрос, а `reactions.top_reactors` лежит внутри сообщения. Пост без звёзд и
   донатор из кэша не требуют обращения к сети — значит, и спать незачем. При
   `MESSAGES_INTERVAL_MIN/MAX = 0.05/0.1` прежняя пауза после каждого сообщения
   давала потолок ~10-20 постов/с и ~12 минут «сна» на 10 000 постов; сейчас эта
   пауза применяется к ~130 запросам, а не к 10 000 сообщений.
2. **Пакетное разрешение донаторов.** Все отправители звёзд и источники пересылок
   одной пачки собираются вместе и запрашиваются одним `users.getUsers`
   (до 200 сущностей за запрос) плюс `channels.getChannels` для каналов — вместо
   одного `get_entity` на каждого неизвестного пользователя. Несколько таких
   запросов выполняются параллельно (`CONCURRENCY`).
3. **Кэш «плохих» результатов.** Пользователь, которого не удалось получить
   (`not_found`), запоминается — повторных запросов по нему не будет, даже если он
   встретится в десятках постов.
4. **Отсутствие лишних ожиданий Telethon.** `HISTORY_WAIT_TIME=0` отключает
   встроенную паузу 1 с между пачками истории (Telethon включает её при
   `limit > 3000`): на 50 000 постов это минус ~8 минут. Темп вместо неё задаёт
   `[DELAY]`.
5. **Адаптивная защита от FloodWait.** После каждого `FloodWait` интервал между
   запросами увеличивается вдвое (потолок 5 с) и работа продолжается — агрессивный
   режим не добивает аккаунт повторными блокировками.

### Что влияет на время прогона

| Фактор | Влияние | Где настраивается |
|---|---|---|
| Пауза между запросами | Очень большое | `[DELAY]`, `[SPEED] PER_REQUEST_DELAY` |
| Запросов на донатора | Большое | `[SPEED] MESSAGE_BATCH`, `ENTITY_BATCH`, `CONCURRENCY` |
| Пауза Telethon между пачками истории | Большое на длинных прогонах | `[SPEED] HISTORY_WAIT_TIME` |
| Прогрев кэша участников | Разовая задержка перед стартом: ~50 запросов на 10 000 участников | `[PARSER] WARMUP_PARTICIPANTS`, `WARMUP_LIMIT` |
| `FloodWait` | Критическое (минуты и часы ожидания) | интервал растёт автоматически; вручную — `[DELAY]`, `CONCURRENCY=1` |
| Прокси и далёкий дата-центр | Среднее: увеличивает время каждого запроса | `[PROXY]` |
| Excel, tqdm, логи | Малое: секунды на десятках тысяч строк | — |

### Замер: `benchmark.py` (офлайн, без Telegram)

Скрипт имитирует канал и сеть и сравнивает старый поштучный обход с текущим
пакетным. Время считается по виртуальным часам (`asyncio.sleep` не ждёт
по-настоящему, а только учитывается), поэтому прогон на 10 000 постов считается
мгновенно, а цифры соответствуют выбранной задержке сети:

```bash
python benchmark.py --count 10000 --latency 0.25
```

```
  постов: 10000, со звёздами: 794 (8%), уникальных донаторов: 399 (в кэше сессии: 60%)
  задержка сети на запрос: 0.25 с, [DELAY]: 0.05-0.1 с

                                       Старый цикл        Новый цикл
Сетевых запросов                                499               132
  из них пакетных (по 200)                       —                32
Виртуальное время прогона              16 мин 14 с              43 с

Ускорение: 22.6× (запросов меньше в 3.8 раза)
```

На «звёздном» канале (`--stars-share 0.4 --reactors 8`) выигрыш больше:
33 мин 47 с против 48 с (**42×**), 4713 запросов против 148 (**в 32 раза меньше**) —
там основной вклад даёт пакетное разрешение донаторов.

### Безопасные значения

| Постов | `[DELAY]` | `HISTORY_WAIT_TIME` | `CONCURRENCY` | `WARMUP_PARTICIPANTS` |
|---|---|---|---|---|
| до 500 | 0.02-0.05 | 0 | 3 | по необходимости |
| 500-5000 | 0.05-0.1 | 0 | 3 | false |
| 5000-50000 | 0.05-0.1 | 0 (при FloodWait — 1) | 2-3 | false, при большом `not_found` — true |
| 50000+ | 0.1-0.3 | 1 | 1-2 | false |

Если пришли `FloodWait` — приложение само замедлится и продолжит, но лучше
вручную поднять `[DELAY]`, поставить `HISTORY_WAIT_TIME=1`, `CONCURRENCY=1` и
`RESOLVE_UNKNOWN_PEERS=false` (донаторы без `access_hash` почти всегда
`not_found`, а запросы тратят лимит).

Бесплатный бонус: `pip install cryptg` ускоряет шифрование MTProto в Telethon
(на парсинге эффект небольшой, но он есть).

## 6. Результат: `output/YYYY-MM-DD_HH-MM-SS_<канал>.xlsx`

Лист **`Stars`**, одна строка = одна пара «пост + отправитель звёзд».

| Колонка | Описание |
|---|---|
| `message_type` | тип сообщения: `text`, `photo`, `video`, `document`, `audio`, `voice`, `poll`, `sticker`, `gif`, `webpage`, `other`; для пересланных — `video(forward)` |
| `reactor_type` | `user` / `channel` / `anonymous` / `unknown` |
| `current_channel` | канал, который парсится (название или username) |
| `current_message_id` | id поста в этом канале |
| `post_link` | прямая ссылка на пост/сообщение (`https://t.me/...`), кликабельная гиперссылка в Excel |
| `original_channel` | канал-источник для пересылок (для обычных постов — как `current_channel`) |
| `original_message_id` | id сообщения в канале-источнике (для обычных постов — как `current_message_id`) |
| `reactor_username` | username отправителя (без `@`); если его нет — имя и фамилия; если определить не удалось — `not_found` |
| `reactor_id` | id отправителя (пусто для анонимных) |
| `stars_count` | сколько звёзд отправил этот отправитель на этот пост |

Оформление: шапка жирным, первая строка закреплена (`freeze_panes = A2`), автофильтр,
ширина колонок по содержимому, id и количество звёзд — целыми числами (формат `0`).

## 7. Согласованные решения по открытым вопросам ТЗ

| Вопрос | Решение | Как поменять |
|---|---|---|
| 1. Точные названия колонок | Оставлены `current_*` / `original_*` из ТЗ (см. таблицу выше) | `models.COLUMNS` |
| 2. Формат `message_type` для пересылок | `video(forward)` — суффикс `(forward)` | `models.FORWARD_SUFFIX` |
| 3. `original_*` для непересланных постов | Дублируют `current_*` (канал и id поста) | в `handlers.build_records_for_message` — поставить `""`/`None` |
| 4. Дополнительные поля | Добавлена только ссылка на пост в колонке `post_link`; дата и другие поля не добавлены | `models.py`, `handlers.py` |
| 5. Файл, если звёзд не найдено | **Не создаётся**, печатается «Звёзды не найдены» | `CREATE_EMPTY_FILE=true` в `[OUTPUT]` или `--create-empty-file` |
| 6. Ссылка на пост | Добавлена колонка `post_link`; для публичных каналов используется `https://t.me/<username>/<id>`, для приватных — `https://t.me/c/<channel_id>/<id>` | формирование в `handlers.build_post_link` |

## 8. Ограничения Telegram (важно понимать)

1. В `top_reactors` Telegram отдаёт **топ**-отправителей звёзд, а не обязательно всех.
   Полный список отправителей через MTProto, как правило, недоступен.
2. Пользователи, скрывшие себя, приходят как анонимные (`reactor_type = anonymous`) —
   определить их невозможно.
3. Чтобы получить username по id, нужен `access_hash` в кэше сессии. Если его нет — в таблице
   будет только id и `not_found`. Помогает `--warmup` (загрузка участников группы обсуждения);
   количество таких записей видно в итоговой сводке.
4. Массовые запросы приводят к `FloodWait`. Паузы из `[DELAY]` применяются между запросами
   к API, при `FloodWait` приложение ждёт `seconds + 1`, продолжает с того же места и
   автоматически увеличивает интервал между запросами (см. раздел 5).

## 9. Логи и коды завершения

`parser.log` (рядом с приложением) — ошибки, FloodWait и сводка по отправителям
(сколько расшифровано, сколько `not_found` — по одной строке на пачку, а не на каждого
донатора). В консоль выводятся только предупреждения, ошибки и итог; подробности —
`--log-level DEBUG`.

| Код | Значение |
|---|---|
| `0` | успех (в т. ч. «Звёзды не найдены» и частично обработанная очередь) |
| `1` | непредвиденная ошибка либо ни один канал очереди не обработан |
| `2` | ошибка конфигурации (`conf.ini` нет / не заполнен / некорректен) |
| `3` | ошибка авторизации (код, 2FA, неверные api_id/api_hash) |
| `4` | нет соединения с Telegram (интернет/прокси) |
| `130` | прервано пользователем (Ctrl+C), сохранены собранные данные |

## 10. Сборка `stars_parser.exe`

```bat
build_exe.bat                     :: Windows: установит зависимости и соберёт dist\stars_parser.exe
```
или вручную:
```bash
pip install -r requirements.txt pyinstaller
pyinstaller stars_parser.spec --noconfirm --clean
```

Положите `conf.ini` **рядом с `dist\stars_parser.exe`** и запустите его: сессия
(`anon.session`), `parser.log` и папка `output` появятся в том же каталоге.
Внутри exe используется `sys.executable`, поэтому пути считаются от расположения exe.

> Статус проверок в репозитории: офлайн-тесты пройдены
> (`pytest` или `python -m unittest discover -s tests`), синтаксис `stars_parser.spec` проверен,
> сценарии приложения проверены вплоть до сетевого вызова Telethon.
> Саму сборку exe в Linux-песочнице выполнить нельзя: в ней отсутствует
> `libpython3.11.so` (PyInstaller требует разделяемую библиотеку Python, а прав на
> `apt install libpython3.11` нет). На Windows сборка штатная — `build_exe.bat`.

## 11. Telegram-бот (aiogram 3.x)

Для удобной автоматизации и работы через Telegram реализован Telegram-бот:
* пошаговый диалог (wizard): каналы → валидация → диапазон (все / N / годы) → режим (все / > порога);
* неблокирующая FIFO-очередь с единым семафором на Telethon-клиент;
* интерактивное обновление прогресса и времени FloodWait;
* отправка итоговой таблицы и сводного Excel-файла (`Donors` + `Summary`);
* раздельные логи: `bot.log` и `parser.log`.

### Запуск бота

1. Добавьте в `conf.ini` секцию `[BOT]` (см. образец в `conf.example.ini`):
```ini
[BOT]
TOKEN=ваш_токен_бота       ; или задайте переменную окружения BOT_TOKEN
ALLOWED_USER_IDS=123456789 ; целые id через запятую
DONOR_THRESHOLD=80
SEND_FILES=true
```
2. Убедитесь, что сессия Telethon авторизована (запустите предварительно `python main.py`).
3. Запустите бота:
```bash
python -m bot.bot_main
```

## 13. Структура проекта

```
main.py          # точка входа CLI, ввод данных, оркестрация
bot/             # Telegram-бот (aiogram 3.x)
  bot_main.py    # точка входа бота, polling, общий loop
  config_bot.py  # чтение и валидация [BOT]
  handlers_bot.py# FSM-диалоги и команды бота (/start, /parse, /queue, ...)
  queue_service.py # очередь задач, семафор=1, отмена, прогресс
  aggregate.py   # агрегация донатеров, порог, сортировка
  formatting.py  # текстовый рендер таблицы, пагинация, экранирование
  access.py      # middleware whitelist проверки
config.py        # чтение и валидация conf.ini (в т. ч. [SPEED])
client.py        # создание и авторизация TelegramClient
handlers.py      # парсинг пачками, пакетное разрешение реакторов, пересылки
speed.py         # профиль скорости и троттлинг запросов (RequestThrottle)
models.py        # dataclass StarRecord, ParseStats, колонки
exporter.py      # Excel (pandas + openpyxl), Donors/Summary и safe_filename
utils.py         # логгер, задержки, работа с текстом и путями
benchmark.py     # офлайн-сравнение скорости: поштучно против пачек
conf.example.ini # образец конфигурации (скопировать в conf.ini)
stars_parser.spec, build_exe.bat, build_exe.sh  # сборка exe через PyInstaller
tests/           # офлайн-тесты (ядро и бот)
```

## 14. Безопасность

`conf.ini`, `*.session`, `parser.log`, `bot.log` и `output/` добавлены в `.gitignore` —
**не коммитите** свои api_id/api_hash и файлы сессий. Значения конфигурации и сессий
в логи и в консоль не выводятся (номер телефона маскируется).
